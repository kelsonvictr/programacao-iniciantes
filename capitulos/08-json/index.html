JSON: a língua dos dados

Antes de guardar dados pra valer, você precisa conhecer o formato em que quase todo programa do mundo guarda e troca informação. Spoiler: ele é o primo gêmeo do dicionário que você já conhece. 📄

O drama clássico de quem ainda não conhece persistência

Você cadastrou 20 alunos no sistema do Capítulo 07…

…aí fechou o PyCharm, foi tomar um café, voltou animado pra continuar — e PUF, sumiu tudo. A lista voltou vazia. O computador "esqueceu". 🫥

Por que isso acontece?

Tudo que mora numa variável fica na memória RAM — que é um lugar rapidíssimo mas volátil. Quando o programa fecha, a RAM é liberada. Os dados somem.

Pra guardar de verdade, a gente precisa escrever os dados num arquivo no disco. Disco é mais lento que RAM, mas não esquece — mesmo se você desligar o computador.

🧠⚡

💾📄

Disco (arquivo)

Onde a gente persiste os dados num arquivo.

Permanece pra sempre.

📓 Pensa num caderno

Você anota os contatos no caderno (escreve no disco). Depois fecha o caderno (fecha o programa). Daqui a uma semana você abre de novo (abre o programa) — e tá lá tudo, intacto. É EXATAMENTE isso que salvar em arquivo faz pelo seu programa.

O que é JSON?
JavaScript Object Notation — texto que parece dicionário

JSON é um formato de texto pra guardar dados. Ele nasceu no mundo do JavaScript (daí o nome), mas hoje TODA linguagem entende — inclusive Python.

E olha que coisa boa: JSON parece QUASE igual a um dicionário Python. Se você sabe dict, você já sabe JSON quase de graça. 🎁

📚 Comparação lado a lado

Olha como é parecido:

Python · dict
na memória Python 
aluno = {
    "nome": "Ana",
    "idade": 22,
    "ativo": True
}
≈ idêntico →
Arquivo · JSON
aluno.json JSON 
{
    "nome": "Ana",
    "idade": 22,
    "ativo": true
}
🔍
Olho clínico: as únicas diferenças são pequenas — em JSON o True vira true (minúsculo) e None vira null. O resto é a mesma coisa. Por isso a gente diz que JSON é "o primo gêmeo" do dicionário Python.
Playground · tradutor Python ↔ JSON

Edita o dicionário Python à esquerda ou o JSON à direita — o outro lado se atualiza sozinho. Tenta os exemplos prontos pra ver as diferenças finas (True vira true, None vira null):

🐍 Python (dict / list)
traduz → ⇄ ← traduz
📄 JSON (arquivo .json)
💡
Sacou a diferença? Mude o True do lado Python pra False e veja virar false no JSON. Tenta colocar None — vira null. São quase a mesma coisa, mas não exatamente.

As regras do JSON
É parecido com Python… mas é mais chato que ele. Repara nas diferenças.

Python é flexível — ele aceita aspas simples, aspas duplas, vírgula sobrando, comentário no meio. O JSON não. Ele é um formato rígido, porque precisa ser entendido por qualquer linguagem do mundo, sem margem pra dúvida.

São 4 regras. Decorou essas quatro, você lê e escreve JSON pro resto da vida. 🎯

1️⃣ Aspas DUPLAS. Sempre.

Nas chaves e nos textos, só vale "aspas duplas". Em Python 'Ana' e "Ana" são a mesma coisa — em JSON, só a segunda existe.

❌ não é JSON
errado JSON 
{
    'nome': 'Ana'
}
conserta →
✅ JSON válido
certo JSON 
{
    "nome": "Ana"
}
2️⃣ true, false e null são minúsculos

Aquilo que em Python é True, False e None, em JSON vira true, false e null. Mesma ideia, escrita diferente. É a pegadinha nº 1 de quem tá começando.

Python
na memória Python 
{
    "ativo": True,
    "premium": False,
    "apelido": None
}
vira →
JSON
aluno.json JSON 
{
    "ativo": true,
    "premium": false,
    "apelido": null
}
3️⃣ Nada de vírgula sobrando no fim

Python deixa você colocar uma vírgula depois do último item (aquela trailing comma confortável). JSON não perdoa: se a vírgula não separa dois itens, ela não pode estar ali.

a vírgula assassina JSON 
{
    "nome": "Ana",
    "idade": 22,   ← essa vírgula quebra tudo 💥
}
4️⃣ Só existem 6 tipos — e comentário não é um deles

JSON é minimalista. Tudo que você guardar nele vai ser uma dessas 6 coisas. E não existe comentário em JSON — nada de # como no Python.

🔤 "texto" String — sempre entre aspas duplas
🔢 22 · 7.5 Número — inteiro ou com vírgula (que é ponto!)
✅ true · false Booleano — minúsculo, sempre
🕳️ null Vazio, sem valor — o None do Python
📋 [ ... ] Array — a lista do Python
🗂️ { ... } Objeto — o dicionário do Python
🧠
Sacou o combo? Um objeto { } pode ter uma lista [ ] dentro. E cada item dessa lista pode ser outro objeto { }. É assim que JSON guarda coisas grandes: encaixando caixinha dentro de caixinha. 🧅 Volta no playground ali em cima e clica em "dict aninhado" pra ver.
🔁
A tradução: dict ⇄ JSON
Como um dicionário vira texto — e volta a ser dicionário

Um arquivo no disco só sabe guardar texto. Ele não faz ideia do que é um dicionário Python. Então, pra guardar seus dados, alguém precisa fazer a tradução — nos dois sentidos:

1. Na memória
🐍 dict / lista Python
traduz
2. Vira texto
📝 aquele texto com chaves e aspas
3. Guardado
📄 texto JSON no arquivo
tempo passa…
4. Traduz de volta
🔍 Python lê o texto
5. Voltou!
🎉 dict / lista de novo, intacto
🪄
Esse vai e volta é a alma da persistência. Enquanto os dados estão na memória, eles são dict e lista — do jeito que você já sabe usar. Quando precisam ir pro disco, viram texto JSON. É a mesma informação, vestida de outro jeito.
📦 E quem faz essa tradução?

O Python já vem com um módulo chamado json (não precisa instalar nada) que sabe traduzir nos dois sentidos. Dá sim pra abrir o arquivo na mão, traduzir na mão e salvar na mão.

Mas isso dá um trabalho danado: você tem que abrir o arquivo, ler tudo, mexer na lista, regravar tudo — toda vez, pra qualquer mudancinha. E ainda tratar o caso de "o arquivo nem existe ainda". 😮‍💨

😎 Boa notícia: você não vai fazer isso na mão.

No Capítulo 09 a gente usa o TinyDB — uma ferramenta que faz essa tradução e essa gravação por você, com comandos curtinhos. Por baixo dos panos ele guarda tudo… num arquivo JSON. Por isso você precisava entender esse formato antes. 🎯

Onde você vai esbarrar em JSON
Spoiler: em basicamente tudo

JSON não é "coisa de aula". É o formato que o mundo inteiro usa pra trocar e guardar dados. Depois de hoje você vai começar a enxergar ele em todo canto:

🌐 APIs
Quando um app pede dados pra um servidor, a resposta quase sempre volta em JSON
⚙️ Configuração
Programas guardam suas preferências (tema, idioma) num arquivo .json
💾 TinyDB
O banco de dados do próximo capítulo salva tudo num .json
🤖 IA
Modelos como o ChatGPT recebem e devolvem dados em JSON o tempo todo
🗣️ JSON é o "inglês" dos programas

Um programa em Python precisa mandar dados pra um site feito em JavaScript, que guarda num banco escrito em Java. Três mundos diferentes — como eles se entendem?

Combinando um idioma comum. Esse idioma é o JSON: texto puro, simples, que qualquer linguagem sabe ler e escrever. É por isso que ele venceu. 🏆

BugZilla apareceu de novo!
Os 3 JSONs quebrados que você VAI escrever um dia
🐛
"Meu JSON tá dando erro e eu não vejo nada de errado!"
Vê se não é uma dessas três — é quase sempre uma dessas três

A mensagem clássica quando um JSON tá torto é essa aqui — e ela aparece tanto no Python quanto no navegador:

erro Terminal 
json.decoder.JSONDecodeError: Expecting property name enclosed in double quotes

Traduzindo do "computês": "tem alguma coisa escrita errada aí, arruma." Bora ver as três culpadas de sempre. 👇

🐛 Bug #1 — usei aspas simples (o vício do Python)

Você digita do jeito que o Python deixa… mas isso não é JSON:

quebrado.json JSON 
{
    'nome': 'Ana'
}
🩹
Conserto: troca TODAS as aspas simples por aspas duplas — "nome", "Ana". Em JSON, aspas simples simplesmente não existem.

🐛 Bug #2 — escrevi True com T maiúsculo

O dedo escorrega e sai o True do Python dentro de um arquivo JSON:

quebrado.json JSON 
{
    "nome": "Ana",
    "ativo": True,
    "apelido": None
}
🩹
Conserto: em JSON é true, false e null — tudo minúsculo. O None do Python nem existe por lá: o nome dele é null.

🐛 Bug #3 — a vírgula sobrando no último item

Esse é traiçoeiro, porque em Python isso é permitido e ninguém reclama:

quebrado.json JSON 
[
    {"nome": "Ana"},
    {"nome": "João"},
]
🩹
Conserto: apaga a vírgula depois do último item. Regra de ouro: vírgula só existe pra separar DOIS itens. Se não tem ninguém depois dela, ela não devia estar ali.
